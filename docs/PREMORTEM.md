# Premortem — Can I Eat?

> "지금으로부터 12개월 후, 프로젝트가 실패했다. 무엇이 잘못되었는가?"

**팀원:** 혜승, 성아, 병찬, 민석

---

## 1. 잘못된 판정으로 신뢰를 잃는다

**시나리오**: 번역이나 분석 결과는 나왔지만, 실제로는 비건·알레르기·식이 제한 판단이 틀려 사용자가 위험한 선택을 하게 된다.

**문제**: 단순 번역 수준에 머물고, 식이 기준별 판단 로직과 위험 성분 해석이 부족하다.

**대응방안**: 번역보다 식이 판단 엔진을 중심으로 설계하고, 불확실한 경우에는 항상 보수적으로 경고한다.

---

## 2. 실제 여행 환경에서 스캔이 잘 안 된다

**시나리오**: 어두운 조명, 반사광, 구겨진 포장지, 작은 글씨, 느린 인터넷 환경 때문에 스캔이 자주 실패하고 사용자가 이탈한다.

**문제**: 데모 환경 중심으로 기능을 만들고, 실제 여행 상황에서의 사용성을 충분히 검증하지 못했다.

**대응방안**: 여행 환경을 전제로 OCR, 촬영 UX, 속도, 오프라인 대응을 우선 최적화한다.
| # | 무엇이 잘못되었나 | 가능성 (1–5) | 영향 (1–5) | 대응책 |
|---|---|---|---|---|
| T1 | OCR 정확도가 낮아 성분표 인식 실패 (손상된 패키지, 조명 불량 등) | 4 | 5 | 다중 OCR 엔진 병렬 사용, 사용자 수동 입력 대안 제공 |
| T2 | 다국어 성분명 번역 오류로 잘못된 안전 판정 | 3 | 5 | 전문 식품 용어 사전 구축, 오번역 신고 기능 추가 |
| T3 | 외부 식품 DB API 서비스 중단 또는 정책 변경 | 2 | 5 | 자체 DB 구축 병행, 복수 API 소스 연동 |
| T4 | 오프라인 환경(해외 로밍 불가)에서 앱 작동 불가 | 3 | 4 | 핵심 기능 오프라인 캐싱 지원 |

---

## 3. 데이터는 많아졌지만 정확하지 않다

**시나리오**: 사용자 업로드와 커뮤니티 데이터는 계속 쌓이지만, 성분 변경·오류 정보·광고성 데이터가 섞이며 결과의 신뢰도가 떨어진다.

**문제**: 데이터 검증과 최신성 관리 체계가 약하다.

**대응방안**: 공식 데이터와 사용자 데이터를 분리 관리하고, 검수·신고·재검증 체계를 운영한다.
| # | 무엇이 잘못되었나 | 가능성 (1–5) | 영향 (1–5) | 대응책 |
|---|---|---|---|---|
| P1 | 식이 프로필 설정이 복잡해 온보딩 이탈 | 4 | 5 | 빠른 프리셋 제공 (비건, 견과류 알레르기 등), 나중에 수정 가능하도록 설계 |
| P2 | "먹어도 됨/안 됨" 판정 결과를 사용자가 신뢰하지 못함 | 3 | 5 | 판정 근거 투명하게 표시, 면책 고지 명확화 |
| P3 | 식당 메뉴 검색 결과가 실제 조리법과 다름 | 3 | 4 | 사용자 제보 기반 데이터 보완, 신뢰도 표시 |
| P4 | 일회성 스캔 후 재방문 동기 없음 | 4 | 4 | 여행 기록, 안전 식품 즐겨찾기, 커뮤니티 공유 기능 추가 |


---

## 4. 초기에 쓸 만한 정보가 부족하다

**시나리오**: 초기에는 검색 결과와 검증된 데이터가 부족해, 사용자가 "쓸모없는 앱"이라고 느끼고 떠난다.

**문제**: 데이터 네트워크 효과가 생기기 전까지 초기 가치가 약하다.

**대응방안**: 초기에는 주요 국가와 대표 식품 데이터를 직접 구축해 최소한의 유효 가치를 먼저 만든다.
| # | 무엇이 잘못되었나 | 가능성 (1–5) | 영향 (1–5) | 대응책 |
|---|---|---|---|---|
| M1 | 네이버·구글 번역 앱이 유사 식품 안전 기능 출시 | 2 | 5 | 식이 프로필 기반 개인화 및 커뮤니티 데이터 차별화 강화 |
| M2 | 타겟 사용자(해외 거주 외국인, 식이 제한 여행자)가 앱 존재를 모름 | 4 | 4 | 비건·알레르기 커뮤니티 마케팅, 여행 앱과 제휴 |
| M3 | 국가별 식품 표기법 차이로 성분 분석 범위가 특정 국가에 치우침 | 3 | 3 | 초기 서비스 국가를 한국·미국으로 한정 후 점진적 확장 | |

---

## 5. 기존 앱과 차별성이 약하다

**시나리오**: 사용자 입장에서 기존 바코드 스캔 앱과 큰 차이를 느끼지 못해 선택받지 못한다.

**문제**: 핵심 기능이 기존 서비스와 유사하게 보인다.

**대응방안**: 바코드뿐 아니라 손글씨 메뉴판, 식당 메뉴, 길거리 음식 등 비정형 음식 정보 해석을 핵심 차별점으로 가져간다.
1. **잘못된 안전 판정** — OCR 오류 또는 번역 실수로 "먹어도 됨" 오판 시 사용자 건강에 직결 → 대응: 다중 검증 레이어 + 근거 표시 + 면책 고지
2. **온보딩 이탈** — 프로필 설정이 번거로워 첫 사용에서 이탈 → 대응: 프리셋 기반 빠른 시작 제공
3. **재방문 동기 부족** — 스캔 한 번으로 끝나는 일회성 사용 → 대응: 여행 기록 및 즐겨찾기 등 지속 사용 유도 기능
