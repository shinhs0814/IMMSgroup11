## Problem Statement

Immigrants, expats, and international students living in countries where food labels are in a non-native language — particularly those with dietary restrictions (allergies, vegan, diabetic, celiac, etc.) — have no reliable way to quickly verify whether a packaged food product is safe to eat.

The current workaround is slow and anxiety-inducing: photograph the label, open Google Translate or Papago, translate the ingredients list, then manually research each unfamiliar ingredient against their dietary profile. This takes 5+ minutes per product and still leaves uncertainty.

The gap is sharpest for non-Latin scripts: Korean (Hangul), Japanese (kanji/hiragana), Thai, Arabic, and Chinese ingredient lists are unsupported or poorly handled by every existing scanner app (Soosee, Fig, NoAllergen). An LLM-first approach can read any script zero-shot — no per-language OCR model required.

## What Makes This Cool

Two things:

1. **Non-Latin script support.** The first food safety scanner that works in Seoul, Bangkok, Tokyo, and Cairo — not just Paris and Berlin. One tap on a Korean ramen packet → red NO with "contains shrimp extract (새우)" → in the user's language.

2. **Safety Passport.** A shareable QR-code dietary profile that renders in the recipient's language. You hand a restaurant server your phone, they scan the QR, they see a clean one-page card in Korean (or Thai, or Arabic) showing exactly what you cannot eat with severity levels. The app becomes a communication bridge between the person with dietary restrictions and the person handling their food — not just a personal lookup tool.

## Constraints

- Planning stage, no code written
- Mobile app (platform: React Native / Expo — enables iOS + Android from one codebase)
- Target: first usable demo in 1-2 weeks, not months
- Real users to test with: expat communities (Korea, Japan, Southeast Asia focus areas)
- No significant budget — must use free tiers and pay-per-call APIs

## Premises

1. **Primary user:** Immigrants, expats, and international students living in a country where food labels are in a non-native language. Daily use, high stakes (health consequences), willing to pay for a reliable solution. NOT occasional tourists.

2. **Core differentiation:** Collapse translate → research → decide into one tap, with a personalized verdict (not just information). Works regardless of label language or script.

3. **LLM extraction is viable but needs confidence UX:** GPT-4o Vision (or equivalent) can extract ingredient lists from label photos in any language/script. For safety-critical verdicts, confidence scores and "verify before eating" fallbacks are non-negotiable.

4. **Community data is the long-term moat:** Every scan should harvest data for a future community layer from day one, even if users never see it yet. The AI pipeline should be designed with this in mind.

## Approaches Considered

### Approach A: AI Pipeline Only (Throwaway Prototype)
**Summary:** Scan → LLM verdict loop. No backend, no accounts, local profile only. NOT a viable path — no data harvesting violates Premise 4, and no Safety Passport means no viral loop. Useful only as a 48-hour proof-of-concept before building Approach B.
**Effort:** S | **Risk:** Low
**Pros:** Testable in 48 hours. No infrastructure. Proves the core extraction works before Approach B setup.
**Cons:** No differentiation from competitors once they add LLM. No Safety Passport. No data harvesting. LLM costs pile up without monetization.

### Approach B: AI Pipeline + Safety Passport (Recommended)
**Summary:** Approach A core, plus Supabase-backed profile sync and shareable QR dietary profile that renders in the recipient's language.
**Effort:** M | **Risk:** Low-Med
**Pros:** Safety Passport is the "whoa" moment and viral loop. Profile sync across devices. QR mechanic is shareable and press-worthy in expat communities.
**Cons:** Requires Supabase setup (+1-2 days). QR card needs server-side localization.

### Approach C: Open Food Facts + LLM Fallback
**Summary:** Barcode scan → OFF lookup. If not found (common for Asian products), fall back to LLM label scan.
**Effort:** M | **Risk:** Med
**Pros:** Fast + accurate for 5M products already in OFF. OFF is open source and can be referenced for allergen taxonomy.
**Cons:** Two code paths. OFF data is sparse for non-Western markets — exactly the users you care most about. Barcode not always readable. Not selected.

## Recommended Approach

**Approach B: AI Pipeline + Safety Passport.**

**Data flow:**
```
camera → [edge fn] → GPT-4o Vision (extraction only) → [same edge fn, step 2] (match against profile) → verdict response
```
One edge function, two sequential steps inside it. GPT-4o does extraction; step 2 does restriction matching. No second invocation.

**Tech stack:**
- **React Native (Expo)** — iOS + Android, one codebase, fast iteration
- **GPT-4o Vision API** — label photo → structured ingredient JSON, any script
- **Supabase** — user profile storage, scan history (community data harvest), Safety Passport URL generation
- **Edge function (Supabase Edge / Vercel)** — two-step: (1) call GPT-4o for extraction, (2) match ingredient list against user profile
- **QR generation** — `react-native-qrcode-svg`; QR links to a web-rendered card

**Auth model:**
- v1: Device UUID (anonymous, no sign-in required). Passport URL = `canieat.app/passport/{device_uuid}`.
- v2: Email / social login (Google, Apple). Migrate device_uuid profile on first sign-in.

**Cost awareness (GPT-4o Vision):**
- ~$0.003–0.006 per image at current pricing (768-token image input). At 500 scans/day = ~$1.50–3/day. Free tier + modest pay-per-use is viable for Phase 1-2. Phase 3 requires caching or a cheaper fallback model (Gemini Flash at ~10x lower cost).

**Restriction profile schema (v1):**
```json
{
  "device_id": "uuid",
  "restrictions": [
    {
      "type": "allergy" | "intolerance" | "preference",
      "name": "shrimp",
      "severity": "critical" | "moderate" | "mild",
      "aliases": ["shrimp extract", "새우", "えび", "crevette"]
    }
  ],
  "language": "en" | "ko" | "ja" | "th" | "ar"
}
```
Scaffold from EU Top-14 allergens. User can add custom entries.

**Confidence model (two separate values):**
- `extraction_confidence`: Elicited from GPT-4o via the prompt — ask GPT-4o to include `"confidence": 0.0-1.0` in its JSON response. Treat as a relative signal, not an absolute one.
- `verdict_confidence`: Computed by the edge function. Heuristic: 1.0 = exact alias match; 0.6 = fuzzy substring match; 0.3 = derived-ingredient inference.
- Combined threshold (provisional): `min(extraction_confidence, verdict_confidence)`
  - ≥ 0.8: show SAFE / UNSAFE verdict normally
  - 0.5–0.8: show verdict with "UNCERTAIN — verify before eating" warning
  - < 0.5: show "Cannot determine — photograph label more clearly"

**Error states (user-facing):**
1. Low confidence (< 0.5): "Label unclear — try again in better light"
2. Non-food image detected: "This doesn't look like a food label"
3. API failure / timeout: "Check failed — scan again or enter ingredients manually"

**Scan log schema (community data harvest):**
```json
{
  "scan_id": "uuid",
  "device_id": "uuid",
  "timestamp": "ISO8601",
  "language_detected": "ko",
  "ingredients_raw": ["새우", "밀가루", "..."],
  "ingredients_normalized": ["shrimp", "wheat flour", "..."],
  "extraction_confidence": 0.91,
  "verdict": "UNSAFE",
  "flagged_restrictions": ["shrimp"],
  "image_hash": "sha256 of label image"
}
```

**Safety Passport (v1 scope):**
- URL: `canieat.app/passport/{device_uuid}`
- v1: English-only static HTML card. Hardcoded Korean and Japanese string translations for the 14 EU allergen names.
- v2: Accept-Language header drives localization. RTL scripts (Arabic) and dynamic i18n are Phase 2.

## Open Questions

1. **Latency validation.** GPT-4o Vision calls run 3-8 seconds. Spike this with a real label photo on a mobile device before committing to the SLA.
2. **Test corpus before any real-user exposure.** Minimum: 50 labels across 5 scripts (EN, KO, JA, TH, AR), 3 degraded image types. Set a pass-rate threshold (≥95% ingredient recall) before beta users.
3. **Verdict confidence threshold tuning.** Provisional thresholds (0.8 / 0.5). Tune empirically against the test corpus before shipping.
4. **Dietary profile taxonomy depth.** Consider sourcing from FAO allergen databases or having a dietitian review the top-14 scaffold.
5. **Monetization.** Free tier with X scans/month? Safety Passport as a premium feature? Decide before Phase 2.
6. **Legal.** Clear disclaimer UX ("This app is not medical advice") is non-negotiable before public launch.

## Success Criteria

- **Week 2 milestone:** Safety Passport QR live, shareable link renders English card correctly
- **Real user signal:** 5 expats test it on real local products and give "I would actually use this" feedback
